# 部署与配置

面向自建 PixelPrint 的部署者；普通使用者请从[使用指南](../使用指南.md)开始。

## Docker Compose 快速部署

```bash
npm ci
npm run setup -- --docker
# 编辑项目生成的 project.config.json
export PIXELPRINT_DB_PASSWORD='替换为自己的数据库密码'
docker compose up --build -d
```

部署前使配置中的数据库密码与 Compose 一致。部署后每位用户在“模型凭据”填写自己的模型地址、模型名称和 API Key；平台默认模型用于兼容未绑定个人凭据的历史会话。首次构建需要访问 npm、Python 和 Chromium 下载源。镜像前端构建将 Node 堆上限设为4GiB，部署机器需预留相应构建内存；该设置仅作用于构建阶段。

应用默认访问 http://localhost:8080，使用初始化生成的账号密码登录。具体初始化和字段说明见[配置说明](configuration.md)及根目录[快速开始](../../README.md)。

## 本地启动

```bash
npm ci
npm run setup
docker compose up -d mysql redis
npm run db:init
npm run prepare:images
npm run prepare:preview
npm run dev
```

以上步骤需要 Node.js 24、可访问的数据库与缓存。Linux 浏览器系统库安装需要相应权限。预览固定为 local；Compose 部署的是整个应用，Node/Vite 和 Chromium 在应用容器执行。

## 持久化与配置保护

`project.config.json` 是服务端私有配置，修改后重启；不要提交真实账号密码、模型凭据、Cookie 密钥或加密密钥。已有配置不会被 setup 自动覆盖。

数据库、Redis、本地文件目录或 S3 对象应按部署方案持久化。正文和检查点的历史加密密钥必须随数据备份保留，不能随意重置；已有数据库升级需先执行对应增量迁移，统一入口见[数据库 SQL](../sql/README.md)。

容器内的 localhost 指向容器自身，模型与存储地址必须能从应用容器访问。文件公共读取地址需要浏览器可达；私有正文对象与公开素材的访问边界不同，不应上传私密文件作为公开图片。

## 发布后检查

实际验证登录、Figma 访问、页面生成、预览、真实点击/滑动、作品保存和下载。运行数据仍以部署环境为准，离线测试不替代上线检查。
