# PixelPrint 使用指南

## 第一次生成页面

1. 从宣传首页点击“在线体验”或“进入工作台”，使用 GitHub 登录，或选择访客体验；本地账号入口仍可使用管理员提供的账号密码。访客在本浏览器临时有效，退出、过期或清除 Cookie 后无法找回，GitHub 登录会使用独立账号。
2. 在“模型凭据”填写本人模型 Base URL、模型名称和 API Key（需支持工具调用）；在“Figma 凭据”保存本人 Token，确认有权访问设计稿。
3. 创建工作区时默认选择公开团队，所有登录用户和访客可共同编辑、对话；需要私有内容时选择“个人”，也可选择其他所属团队。
4. 新建会话，选择 H5 或 RN 目标并绑定具体 Figma 节点链接。已填写设计稿的新会话会自动启动 D2C，可继续补充需求。
5. 在对话中查看阶段说明和工具过程，在右侧查看源码、素材和运行预览。
6. 结果满意后暂存版本、保存作品或下载文件，按页面提供的入口操作。

同一个页面的后续调整继续使用原会话；独立页面使用新会话，避免混用需求和产物。

## 如何描述修改

尽量写清目标、交互和保留范围。例如：

> 保留当前布局、图片和文案。点击某个名字后，让它滚到中间；支持左右滑动和首尾循环。修改后验证点击与滑动效果。

只想换肤时明确“只换图片和颜色，保留结构、尺寸、文案和交互”；可提供多个主题设计链接。模型会复用现有产物，按本次修改范围处理。

## 查看预览和交互验收

- 使用预览的手机比例、横竖屏和全屏入口检查页面；在线编辑修改后，以新修订构建结果为准。
- 编译成功表示页面可以构建；规则通过、视觉还原正确、交互符合需求是不同结论。
- 已有页面的交互修改可使用真实浏览器点击、触摸或鼠标滑动，并核对选中态、滚动位置及回环。
- 只有截图或“元素可见”不能证明交互生效。验收通过后交付；一轮验收加最多两次复验仍未通过时，会说明未完成项并保留进度。
- 截图保留 12,000 像素高度和 10MiB 大小保护。页面底部可定点截图；局部截图不表示整页已验收，提示会区分高度、字节和内部滚动范围。

## 执行中补充要求、暂停与继续

执行中发送的消息可能先进入队列；需要及时调整方向时使用页面提供的即时引导入口。新要求会在后续处理时生效，不会撤回已经执行的工具操作。

暂停后已保存文件和进度保留。继续会复用可用检查点，核对已完成结果；并不保证所有外部操作都可无条件重放。普通继续不重置交互验收预算，明确的新要求会重新核对范围。

看到失败时，在“执行诊断”查看错误明细，保留 runId 和排查编号；同时说明预期、实际表现及截图，便于定位。不要仅凭“执行结束”判断所有检查均已通过。

## 在线编辑和保存

工作区在线编辑先使用独立副本；保存副本与应用回会话源码是不同操作。确认后通过明确的应用入口写回，发生修订冲突时先核对差异。

临时草稿有过期机制，长期保留请保存作品、暂存版本或下载。不同入口能执行的操作以当前权限和界面为准。

## 团队、广场和作品库

- 所有用户（含访客）默认属于公开团队；新工作区默认公开协作，已有个人工作区保持私有，创建时也可主动选择“个人”。普通团队由创建者管理成员。
- 每个人使用自己的Figma Token；公开及其他团队的每个新轮次使用实际发起人自己的模型API连接。问题回答和中断恢复必须由原发起人继续使用原轮次凭据，不能借用他人或平台Key。
- 公开会话对所有已登录用户可见，包含允许展示的聊天、工具过程和子 Agent 记录。公开前确认内容适合共享，只有有权的会话创建者或历史兼容拥有者可公开或撤回。
- 广场访客可查看产物，编辑自己的副本并保存到本人作品库或下载；不能覆盖原作者的工作区。
- 本人作品可再次编辑；撤回公开不能收回他人此前已下载或保存的副本。有权限时可跳转来源会话。

## 常见问题

| 现象 | 建议 |
| --- | --- |
| Figma 无权访问 | 检查本人 Token、设计稿权限和绑定节点链接 |
| 生成时暂时无法预览 | 查看是否仍在保存依赖文件；等待当前修订编译，失败时检查诊断 |
| 截图只包含部分内容 | 根据覆盖提示检查目标区域，不把未出现的区域当作通过 |
| 模型说完成但效果不对 | 明确指出元素、预期与实际表现，附当前修订截图并要求对应动作验收 |
| 暂停后继续仍有问题 | 保留会话，在诊断中提供 runId、排查编号和最近操作 |

## 功能与权限一览

PixelPrint 把设计稿读取、素材准备、代码生成、预览、持续修改与作品保存放在同一个工作台中。当前生成目标包括 H5 和 RN，RN 的网页预览不替代原生设备验收。

| 功能 | 使用者可以做什么 |
| --- | --- |
| 工作区与会话 | 管理独立页面、需求上下文和产物；固定工作区资源版本 |
| Figma 凭据与设计稿 | 使用本人凭据访问指定节点，生成时准备图片与结构信息 |
| AI 持续修改 | 在原会话补充布局、换肤和交互需求，保留既有产物与进度 |
| 运行预览 | 查看当前修订，选择手机比例、横竖屏和全屏展示 |
| 交互验收 | 使用真实点击、滑动和状态断言检查本次修改 |
| 在线编辑 | 编辑临时副本，确认后应用回有权修改的工作区 |
| 团队协作 | 在所选团队中共享工作区，成员共同编辑与对话 |
| 会话广场 | 向已登录用户公开会话，查看他人的聊天过程和产物 |
| 个人作品 | 保存自己的编辑副本、再次编辑或下载；不覆盖原作品 |
| 执行诊断 | 查看模型用量、请求耗时、错误次数及排查信息 |

执行完成、文件保存、编译成功、规则通过和视觉/交互效果正确分别判断。实际可用功能取决于部署版本、权限、模型能力和配置。

## D2C 能力与验收链路

| 阶段 | 能力与可检查结果 |
| --- | --- |
| 设计事实 | 核对版本、保存完整节点缓存与设计基准图，识别页面和区块 |
| 素材准备 | 按契约切图、英文命名与去重、尝试无损压缩、上传并登记地址 |
| 设计规则 | 程序扫描确定性事实，模型补疑难项，形成 rule-hits.json |
| 页面实现 | 消费命中约束，主子任务按范围出码，保存源码、样式和素材使用说明 |
| 代码规则 | 区块自检与整页 merge 检查，结论绑定实际源码修订 |
| 运行与视觉 | 构建预览、检查缺图和运行错误、对照设计基准与真实截图 |
| 交互与交付 | 实际点击/滑动及状态断言，说明验收范围、未完成项并保存结果 |

各阶段怎样衔接、为什么不能互相代替，见[D2C 生成与验收流程](D2C生成与验收流程.md)。

开始使用请阅读[使用指南](使用指南.md)，整体过程见[架构与流程图](架构与流程图.md)。
