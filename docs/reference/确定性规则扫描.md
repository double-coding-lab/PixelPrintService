# 确定性规则扫描

## 执行链路

`delegate_agent(role=rule_scan)` → `GenerationTools.scanRules` → `ruleScan.scanDesignRules` → 原授权文件写入 → 无疑难项直接返回 / 有疑难项进入原子Agent → 原交付复核 → 生成代码 → 原 `check_rules`。

扫描计算只读取本轮恢复的完整Figma缓存、配置及工作区冻结规则包。计算不联网、不执行脚本、不自行保存。报告使用现有租约、文件修订、MySQL正文和时间线保存，不新增表、配置或进程。

## 分工

- `run/ruleScan/facts.ts`：真实节点索引、范围、隐藏、切图后代、列表副本与父子关系。
- `run/ruleScan/adapters.ts`：H5/RN期望差异与参数。
- `run/ruleScan/index.ts`：规则触发、待模型判断项、生成后待检查项及输入指纹。
- `run/ruleScan/compatibility.ts`：当前已审阅规则文件的摘要。
- `run/ruleScan/report.ts`：保留程序结果、接纳授权疑难项和核对完成状态。
- `run/agent/agent.ts`：沿原子任务启动、保存、恢复和交接；纯程序扫描不产生子模型请求。

## 报告

- `hits`：确定性设计命中与模型确认的疑难命中，保持原格式。
- `constraints`：布局、单位、颜色来源等实现约束。
- `deferredChecks`：必须在有源码后核对的检查；不表示通过。
- `nativeScan`：输入指纹、程序覆盖、未支持规则及待评审节点。
- `nativeReview`：每批补交须携带当前nativeScan.fingerprint；逐条疑难判断 `{rule,nodeId,decision:"hit"|"not_applicable",reason}`。命中须有真实hits；未命中也须理由。

模型只能补充待评审规则/节点，程序命中和报告头由平台重建。报告结构有效、口头完成或complete=true均不能跳过未判断项。规则R11复杂几何及未标注列表的R15候选保留模型判断；R10等依赖源码的实际违规仅留到生成后核对。

## 跨端与版本

当前支持H5/RN。节点事实共用，fixed定位、渐变、背景图、flex默认方向、单位及页面/区块骨架分别适配。xTaro等未知目标明确拒绝，不回落到H5/RN，也不承诺已支持其生成或预览。

当前算法对照内置PixelPrint 1.6.1规则。新增、缺失、修改规则或README变化进入模型复核；未知规则的根节点评审覆盖授权范围，实际命中仍绑定真实节点。更新PixelPrint不会自动认证新规则，需核对语义后更新对应算法和摘要。

指纹包含算法修订、目标、配置、规则及节点事实。时间戳不影响指纹。同输入已有疑难判断可恢复，输入变化重新判定；旧失败记录不会改写。缓存不完整时交回父Agent补齐，存储/失租/取消仍阻断。

## 验证边界

离线测试使用真实冻结规则、假模型、内存检查点和临时文件，不请求真实模型、Figma或对象存储。子模型请求数减少可通过诊断确认；线上模型理解、真实设计稿效果及端到端提速需发布后同稿对比。程序扫描不代替原有代码规则、图片与视觉验收。
