# PixelPrint 系统能力清单


核对日期：2026-11-24。范围：当前社区版实现；“已实现”表示已有对应代码入口，不代表已部署到生产或所有设计稿均通过验收。系统关系见[架构与流程图](架构与流程图.md)。

## 1. 汇报摘要

PixelPrint 是面向用户的设计转代码工作台：以工作区固定 Skill 与配置，以会话管理独立代码和上下文，把 Figma 读取、切图、代码生成、规则检查、运行预览、截图反馈、在线编辑及版本下载串成持续迭代流程。当前支持 H5 和 RN Web 兼容预览。

用户能看到工作区、聊天、文件、预览和版本；后台负责持久化任务、执行租约、模型与工具循环、子 Agent 分工、检查点和摘要、隔离编译、对象存储及故障诊断。关闭浏览器后任务可以继续，用户返回后读取已保存的过程与产物。

适合当前汇报的结论：**工作台和持续调整的主要链路已有实现，下一步重点是目标环境稳定性、长会话收敛和真实设计还原质量验收。** 不把“任务执行结束”“规则检查通过”“视觉正确”混为一个成功状态。

## 2. 用户直接可见的能力

| 能力 | 用户怎样使用 / 看到什么 | 实现入口 | 边界 |
| --- | --- | --- | --- |
| 账号登录 | 本地账号密码登录，签名 Cookie 保存登录态；另支持个人 API Token | `src/hooks/http/identity.ts`、`src/hooks/http/auth.ts` | 账号由部署配置管理，密码使用 scrypt 哈希，公开内容仍需登录 |
| 工作区管理 | 创建、切换、查看、删除工作区 | `workspace.ts`、`workspace/service.ts`、`WorkspacePanel.tsx` | 删除为软删除；有未结束任务时受状态约束，暂无恢复/物理清理入口 |
| 固定资源与配置 | 查看当前 Skill/配置修订，编辑 H5/RN 生成配置，显式升级资源 | `workspace/resources.ts`、`workspace/service.ts` | 已有工作区保持自己的资源修订，开发者更新包不会自动替换它 |
| 独立会话 | 同一工作区创建多份 H5/RN 产物、切换聊天与文件 | `session/service.ts`、`SessionPanel.tsx` | 会话间文件和模型上下文隔离；调整现有产物沿用原会话 |
| 设计稿关联 | 创建会话时绑定 Figma 链接，页面显示可点击链接 | `session.ts`、`SessionPanel.tsx` | 聊天随手贴链接不等同于更新会话绑定 |
| 个人模型凭据 | 保存自己的模型 Token，广场分支使用本人凭据 | `credential/service.ts`、`ModelCredentialSettings.tsx` | 服务地址和模型由管理员配置，个人 Token 加密并固定修订 |
| Figma 凭据 | 设置本人 Token、查看配置状态 | `credential/service.ts`、`CredentialSettings.tsx` | 服务端加密保存，不在工作区配置或前端返回明文 |
| 持续对话生成 | 发送需求，Agent 读取 Skill、调用工具、保存源码，再继续调整 | `run/agent/agent.ts`、`ConversationView.tsx` | 生成质量取决于固定 Skill、设计稿、模型与实际检查结果 |
| 运行中发消息 | 普通消息进入待发送列表；可删除、立即发送 | `session/queue.ts`、`MessageQueue.tsx` | 排队内容先保存；即时引导在下一次主模型调用前接收，不强行终止在途工具 |
| 业务问答 | Agent 缺少业务决策时显示问题、选项和自由回答 | `run/interaction.ts`、`QuestionPanel.tsx` | 回答后恢复同一轮，区别于新建任务；可明确结束等待 |
| 暂停与继续 | 停止运行、继续已暂停/中断的任务 | `session/messages.ts`、`SessionPanel.tsx` | 协作式取消；已提交文件保留，结果未知的副作用不会自动重放 |
| 图片反馈 | 粘贴/上传截图并附文字，交模型分析调整 | `session/attachments.ts`、`MessageImages.tsx` | 图片格式/大小及归属受校验，依赖模型图像能力和 文件存储（local/S3） |
| 实时执行过程 | 显示阶段、工具摘要、文件变化、切图进度；结束后收起过程 | `TimelineActivity.tsx`、`ConversationRound.tsx` | 展示安全摘要与供应商明确返回的公开思考内容，私有检查点和凭据不公开 |
| 子 Agent 过程 | 查看规则扫描、UI 实现等子任务的公开过程 | `SubagentPanel.tsx`、`run/subagent.ts` | 子任务共享当前 Run 的预算和租约，不能无限递归派发 |
| Markdown 回复 | 正文支持列表、表格、代码块等展示 | `web/src/components/MarkdownMessage.tsx` | 展示消息内容，不在主站执行生成代码 |
| 产物目录与读取 | 文件树查看源码、文本、图片，按文件类型预览 | `FilesPanel.tsx`、`FilePreview.tsx` | 只读查看与“在线编辑”是两条明确操作 |
| 当前会话运行预览 | 无需先暂存版本，代码变动后构建并刷新预览 | `preview/session.ts`、`SessionPreviewPanel.tsx` | 首次或输入变更需编译；命中缓存不重编译 |
| H5 自适应 | 在受控构建中进行 px2vw 转换，可切换预览宽度 | `preview-template/`、`preview/session.ts` | 转换按固定生成配置执行；切换宽度仅调整展示，不重新编译 |
| RN Web 预览 | React Native 组件通过浏览器兼容层展示 | `preview-template/`、`preview/runtime.ts` | 包含 rpx/静态资源适配，浏览器效果不等于原生设备效果 |
| 设计稿截图 | 与运行预览、源码资源并列查看已保存的根节点截图 | `run/designReference.ts`、`DesignReferencePanel.tsx` | 老会话缺图显示空态；截图不等于锁定未来 Figma 修订 |
| 元素审查 | 悬停/点击查看节点、选择器、尺寸与样式，定位源码 | `preview/inspector.ts`、`PreviewInspector.tsx` | 是受限预览内的审查能力；选择器匹配和源码定位有覆盖边界 |
| 预览调试面板 | 按需打开 Eruda 查看元素、日志和请求 | `preview/debugger.ts`、`PreviewDebugger.tsx` | CSP 继续生效；面板修改只影响当前 DOM，不自动写回源码 |
| 在线编辑 | Monaco 查看/编辑已有源码、类型提示、格式化、保存预览 | `EditWorkspace.tsx`、`CodeEditor.tsx` | 操作临时副本，保存副本与应用稳定源码分开；草稿固定 2 小时到期 |
| 入口切换与全文搜索 | 切入口并保存构建；大小写/整词/正则搜索，点击跳到命中 | `EditorSearch.tsx`、`globalSearch.ts` | 独立 Worker 可超时终止；搜索规模有界，结果提示截断，行列保持准确 |
| 应用在线修改 | 显式应用到会话，必要时先暂停 Agent、完成后继续 | `edit/service.ts`、`editRunControl.ts` | 同文件并发冲突拒绝覆盖；浏览器离开可能保留暂停状态 |
| Agent 运行截图反馈 | Agent 构建和截图检查后，真实图片出现在聊天中 | `run/screenshots.ts`、`preview/inspection.ts` | 需要本地 Chromium 及系统库；环境缺失显示失败，不伪造截图 |
| 版本暂存 | 名称可选、默认命名，后台冻结打包，显示保存状态 | `version/service.ts`、`VersionsPanel.tsx` | 只冻结当次内容；后台保存失败需按状态处理，浏览器关闭不取消打包 |
| ZIP 下载与作品库 | 下载版本，区分本人/全部用户作品，查看冻结文件和预览 | `version/gallery.ts`、`WorksPanel.tsx` | 他人作品投影与私有聊天分开，版本内容不随当前代码变化 |
| 规则状态 | 看到已通过、未通过、待检查等状态 | `ValidationNotice.tsx`、`run/tools.ts` | 执行成功与产物合规独立，静态规则通过不保证视觉还原 |
| 执行诊断 | 查看模型/工具耗时、失败分类、排查编号、已知用量 | `run/diagnostics.ts`、`DiagnosticsPanel.tsx` | 旧数据缺失显示未知，不能事后补回供应商未报告的 Token |
| 工作台效率 | 会话搜索、长标题查看、导航收起、对话缩放/全屏、版本区折叠 | `SessionMenuItem.tsx`、`SessionPanel.tsx` | 属于当前自建 React 工作台交互 |

后端相对入口位于 `src/functions/d2c/`；前端相对入口位于 `web/src/workspace/`，表内已写完整前缀者除外。

## 3. 用户通常看不到、但系统已承担的能力

| 后台能力 | 实际作用 | 事实来源 / 边界 |
| --- | --- | --- |
| 基础连接与日志 | 使用 mysql2/Sequelize、node-redis、Pino 和项目内配置 | `src/hooks/tools/`；对象保存使用 local 或 S3 驱动 |
| 前后端同域 | 一个 Fastify 应用提供 React 静态页、API、登录及预览网关 | `src/index.ts`、`src/app.ts`；生成页面另在隔离 iframe 中运行 |
| 先持久化后执行 | 消息、输入快照和 queued Run 在事务中保存，Worker 随后领取 | `session/messages.ts`、`run/worker.ts`；HTTP 请求不等待完整生成 |
| 执行预算保护 | 控制并发准入、模型请求数、整轮活跃执行时长及上下文/输出预算 | `src/config/d2c.ts`、`run/agent/agent.ts`；主/子 Agent 共享限额，配置在入队时冻结 |
| 同会话互斥 | 一个会话的活动任务按状态/事务约束串行，其他会话可并行 | `run/leases.ts`；并发额度与数据库准入共同控制 |
| 租约与恢复 | 领取、续租、防旧 Worker 写回、过期回收、停止结算 | `run/leases.ts`、`run/execute.ts`；中断恢复不代表任意操作可安全重放 |
| 幂等请求 | 同一请求 ID 重试复用原消息/轮次/回答，降低网络重试重复写入 | `session/messages.ts`、`session/queue.ts` |
| Deep Agents 循环 | 模型决定工具，框架驱动调用与结果回传 | `run/agent/agent.ts`；当前正式代码保留单一 Deep Agents 执行路径 |
| 检查点恢复 | 持久化 LangGraph 状态与中间写，恢复业务提问及稳定运行上下文 | `run/agent/checkpoint.ts`；图状态、公开聊天、源码分别存储 |
| 自动摘要与完整归档 | 请求前控制上下文体积，摘要保留目标/约束/资料定位，完整历史可按路径读取 | `run/agent/summary.ts`、`context.ts`、`archive.ts`；保守预算估算，仍有上下文限额 |
| 有界子 Agent 并行 | 不同子任务独立模型上下文、分配精确写入范围；共享预算和提交边界 | `run/agent/delegationScheduler.ts`、`subagentTools.ts`；自校验服从授权范围 |
| 工具纠错分级 | 可调整参数/可重试的问题反馈给模型；租约、取消、存储等故障按分类结算 | `run/toolFeedback.ts`、`errors.ts`；并非所有错误都无条件继续 |
| 固定输入与资源修订 | Run 冻结配置和资源引用，工作区升级显式进行 | `workspace/resources.ts`、`run/persistence.ts`；密钥运行时服务端取用 |
| Figma 代理与切图复用 | 外网按可配置代理和白名单访问，正式切图完成后复用可信缓存 | `run/sliceNetwork.ts`、`slices.ts`、`sliceCache.ts`；模型和存储使用各自客户端 |
| 图片地址与上传恢复 | 统一会话对象目录、内容校验、重名后缀、真实 CDN 地址映射 | `src/hooks/tools/storage.ts`、`utils/assetUrls.ts`；通道实际行为需真实环境验证 |
| 稳定源码提交 | 文本/二进制索引、文件修订与时间线受事务和租约保护 | `run/persistence.ts`；磁盘临时副本不是唯一事实源 |
| 提交后通知 | MySQL 事件提交后用 Redis/本地通知唤醒 SSE，再按 seq 读取正文 | `session/events.ts`、`notifications.ts`；低频补读兜底，不以通知当持久消息 |
| 模型请求统计 | 主/子模型和摘要逐请求保存开始/结束及已知用量，失败/中断仍保留已完成记录 | `run/agent/modelActivity.ts`、`usage.ts`；未知值不当作零费用 |
| 隔离构建与运行截图 | 固定模板的本地 Node 编译、Chromium 截图；超时与取消回收进程组，iframe 保持沙盒 | `preview/runner.ts`、`capture.ts`；依赖固定编译包、浏览器及系统库；与主服务共享机器资源 |
| 预览防重复构建 | 输入摘要+文件修订命中复用，本地缓存校验和回收，短票据读取 | `preview/cache.ts`、`service.ts`；本地磁盘丢失可重建，跨实例须验证缓存/路由 |
| 增量编辑预览 | Redis CAS 管副本，复用图片输入和 warm 编译上下文，失败保留原画面 | `edit/store.ts`、`preview/warmRunner.ts`；不是任意依赖在线安装或完整热模块替换 |
| 后台版本打包 | 冻结快照后异步 ZIP，租约与恢复循环接回中断保存 | `version/service.ts`；重试使用原冻结版本，不重新抓当前文件 |
| 凭据与数据边界 | Figma Token 加密；请求/诊断脱敏；附件、会话与写请求检查用户归属/同源 | `credential/service.ts`、`src/hooks/http/`；当前不是完整企业级 RBAC 产品 |
| 预览隔离 | 票据资源网关、CSP、sandbox iframe 和受约束消息通信 | `preview/runtime.ts`、`inspector.ts`；不向生成页面开放主站登录态/任意内网 |
| 可重复联调 | 文件存储（local/S3）、切图、模型用量、检查点、预览/截图等独立调试入口 | `test/integration/`、`package.json`；离线测试与真实外部依赖验收分开 |

## 4. 关键数据保存位置

| 数据 | 保存位置 | 生命周期与用途 |
| --- | --- | --- |
| 工作区、资源修订、生成配置 | MySQL `d2c_workspace` / `d2c_workspace_revision`；资源包在 文件存储（local/S3） | 显式修改/升级，已有工作区保留原修订 |
| 会话、Run、快照、状态、用量 | MySQL `d2c_session` / `d2c_run` | 持久业务记录，用于展示、执行和恢复 |
| 聊天、工具摘要、待发送消息、事件游标 | MySQL `d2c_timeline` | 公开投影和私有历史分字段管理，SSE 可补读 |
| 图检查点、内部历史归档 | MySQL `d2c_agent_checkpoint` / `d2c_agent_write` | 私有运行状态，不直接返回前端 |
| 当前文本源码 / 缓存、二进制索引 | MySQL `d2c_file`；二进制字节在 文件存储（local/S3） | 工具或显式应用时保存；读取受大小/类型等约束 |
| 用户图片与运行截图 | MySQL `d2c_message_attachment` + 文件存储（local/S3） | 消息关联与图像读取，后续调整可引用 |
| 版本、冻结文件与 ZIP | MySQL `d2c_version` / `d2c_version_file` + 文件存储（local/S3） | 已保存版本固定，独立于后续会话修改 |
| 个人模型凭据 | 保存自己的模型 Token，广场分支使用本人凭据 | `credential/service.ts`、`ModelCredentialSettings.tsx` | 服务地址和模型由管理员配置，个人 Token 加密并固定修订 |
| Figma 凭据 | MySQL `d2c_credential`（加密） | 密钥材料从 项目内配置 获取，明文仅服务端使用 |
| 预览状态与构建清单 | MySQL `d2c_preview` | 对应确定输入与运行环境修订 |
| 当前会话预览 | `.runtime/previews/sessions/<sessionId>/<entryHash>/<inputHash>/` | 默认滑动 30 天/根缓存总量 2GiB，LRU 回收；同输入命中复用 |
| 临时编辑草稿 | Redis | 固定 2 小时到期，保存不续期；尚未应用时不等于稳定源码 |
| 编辑预览与图片输入 | `.runtime/edit-previews/`、`.runtime/edit-inputs/` | 可重建本地缓存；滑动 2 小时并定期清理 |
| 执行副本 | `execution.workRoot`，默认 `.runtime/runs/` | 本轮恢复及工具运行使用，结束后清理 |
| 平台运行参数 | 项目内配置 `project.config.json` | 模型、执行限制、网络白名单、文件存储（local/S3）、密钥等 |
| 固定 Skill/脚本来源 | 仓库 `pixelprint/` 和 `VERSION.json` | `npm run pixelprint:update` 手动同步，随服务部署 |

当前使用 **MySQL + Redis + 文件存储（local/S3） + 服务端本地缓存**；MongoDB 未接入。进程内仍有取消句柄、活动任务 Promise、编译缓存等控制数据，它们不替代持久业务记录。

## 5. 汇报时需要单列的边界

| 事项 | 当前口径 |
| --- | --- |
| 任意设计稿一次生成就完全还原 | 不承诺。编译、规则和真实截图都需检查，模型可能反复调整或触及预算 |
| 无限上下文 / 永不中断 | 未实现。已有摘要、恢复和纠错，但模型窗口、轮次请求数、活跃时限及依赖故障仍有效 |
| 完整原生 RN 验收 | 当前提供 RN Web 兼容预览，原生端需独立验证 |
| Xtaro、多人实时共同编辑、角色权限管理 | 当前未作为完整业务能力接入 |
| 官方 Deep Agents UI / React SDK | 当前是自建 React + Antd 工作台，未因后端框架接入而自动使用官方前端 |
| Skill 线上自动追新 | 当前开发者手动更新并发布，工作区另行显式升级 |
| 基础设施/部署验收 | 编译依赖、浏览器系统库、缓存目录、证书、本地账号认证、项目内配置、MySQL、Redis、文件存储（local/S3）和代理均需目标环境具备并验证 |
| 已完成任务是否代表代码可交付 | Run 状态、规则状态、预览构建、视觉质量和业务验收分别记录与判断 |

本清单是能力盘点，不用测试用例数量推算完成率，也不把历史迁移记录中的“后续待做”直接当作当前缺失。

## 预览执行方式

预览固定使用 `local`：在应用所在服务器或容器内用 Node/Vite 编译、Chromium 截图。Docker Compose 部署整个应用；编译与截图仍在应用容器执行。依赖准备见[部署与配置](deployment/部署与配置.md)。

## 当前使用者功能与权限

PixelPrint 把设计稿读取、素材准备、代码生成、预览、持续修改与作品保存放在同一个工作台中。当前生成目标包括 H5 和 RN，RN 的网页预览不替代原生设备验收。

| 功能 | 使用者可以做什么 |
| --- | --- |
| 工作区与会话 | 管理独立页面、需求上下文和产物；固定工作区资源版本 |
| Figma 凭据与设计稿 | 使用本人凭据访问指定节点，生成时准备图片与结构信息 |
| AI 持续修改 | 在原会话补充布局、换肤和交互需求，保留既有产物与进度 |
| 运行预览 | 查看当前修订，选择手机比例、横竖屏和全屏展示 |
| 交互验收 | 使用真实点击、滑动和状态断言检查本次修改 |
| 在线编辑 | 编辑临时副本，确认后应用回有权修改的工作区 |
| 团队协作 | 在所选团队中共享工作区，成员共同编辑与对话 |
| 会话广场 | 向已登录用户公开会话，查看他人的聊天过程和产物 |
| 个人作品 | 保存自己的编辑副本、再次编辑或下载；不覆盖原作品 |
| 执行诊断 | 查看模型用量、请求耗时、错误次数及排查信息 |


执行完成、文件保存、编译成功、规则通过和视觉/交互效果正确分别判断。实际可用功能取决于部署版本、权限、模型能力和配置。

### D2C 能力与验收链路

| 阶段 | 能力与可检查结果 |
| --- | --- |
| 设计事实 | 核对版本、保存完整节点缓存与设计基准图，识别页面和区块 |
| 素材准备 | 按契约切图、英文命名与去重、尝试无损压缩、上传并登记地址 |
| 设计规则 | 程序扫描确定性事实，模型补疑难项，形成 rule-hits.json |
| 页面实现 | 消费命中约束，主子任务按范围出码，保存源码、样式和素材使用说明 |
| 代码规则 | 区块自检与整页 merge 检查，结论绑定实际源码修订 |
| 运行与视觉 | 构建预览、检查缺图和运行错误、对照设计基准与真实截图 |
| 交互与交付 | 实际点击/滑动及状态断言，说明验收范围、未完成项并保存结果 |

各阶段怎样衔接、为什么不能互相代替，见[D2C 生成与验收流程](D2C生成与验收流程.md)。

开始使用请阅读[使用指南](使用指南.md)，整体过程见[架构与流程图](架构与流程图.md)。
