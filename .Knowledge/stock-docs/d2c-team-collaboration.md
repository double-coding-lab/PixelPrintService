# 社区账号与团队协作

## 账号和成员

账号在 `auth.users` 中配置，登录后服务端提供稳定 userId。团队成员保存规范化账号标识，比较时处理允许的大小写和空白兼容；新增账号本身仍由部署配置管理。

团队创建者添加、移除成员，创建者不能被移除。`requireTeamMember()` 在数据库核对团队和成员，不用长期内存缓存替代当前授权。团队写操作与业务写事务遵循固定锁序。

## 工作区可见性

| 场景 | 规则 |
| --- | --- |
| 默认列表 | 本人创建及当前所属团队的工作区 |
| 个人列表 | 本人创建且 teamId 为 NULL 或历史空字符串 |
| 指定团队 | 先校验当前成员资格，再返回对应工作区 |
| 共享详情和编辑 | 原创建者或当前团队成员，仍需业务对象存在 |
| 调整团队归属 | 原创建者操作并复查目标团队条件 |

列表与详情统一使用创建者比较逻辑，避免旧记录只能通过链接访问。历史数据保持原值，权限比较采用服务规范化规则。

## 执行与凭据

共享会话依旧只允许一个活动轮次。消息、Run、排队记录和暂存版本保存实际操作用户；Worker 在执行前复查发起人权限。不同成员不能借即时指导向其他用户的活动运行注入消息，正常排队遵守原规则。

凭据按 ownerUserId 和凭据 ID 管理。团队成员可以共享产物，不能取得其他成员的 Figma Token 或替其解密。平台模型密钥来自服务端配置，不能作为会话业务数据返回。

## 编辑、附件与公开作品

一个有权编辑者的活动编辑副本不会被另一个用户直接覆盖；权限撤销后的占用按服务规则回收。未发送附件草稿保持个人范围，已发会话附件按会话访问权限处理。

私有预览票据每次读取复查会话权限。团队作品按工作区团队归属筛选；公开版本和公开对象有自己的可访问范围，移除团队成员不会撤回已经下载的内容。

## 排查入口

- `team/access.ts`：账号规范化、团队核验、列表过滤和工作区授权。
- `team/service.ts`：创建团队、成员变更与管理权限。
- `session/access.ts`、`messages.ts`、`queue.ts`：共享会话写入、排队和操作者。
- `run/worker.ts`、`run/persistence.ts`：执行资格与真实操作身份。
- `edit/service.ts`、`preview/service.ts`：编辑冲突和预览读取权限。

新增协作能力需要同时核对列表、详情、写入、后台执行和资源读取，不能仅修改页面的菜单可见性。

工作区名称后使用括号标注团队或个人，未知团队沿用有限目录兜底；详见[工作区归属展示](../topics/d2c-team-collaboration.md#工作区名称归属展示)。

## 团队与工作区创建衔接

首页并列提供两个创建入口；工作区归属旁可进入新建团队，创建/取消后返回原工作区表单并保留名称。成功创建的团队作为新归属，目录重新确认后才可提交，成员权限与共享凭据规则保持原约定。
