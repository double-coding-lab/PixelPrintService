# D2C 会话广场与个人作品

## 用户流程

1. 会话创建者点击“发布到广场”，共享聊天、工具过程、子 Agent 记录和产物。未记录创建者的旧会话若属于个人工作区，工作区拥有者也可发布和撤回；团队会话不回退授权。
2. 从顶栏“广场”选择会话，查看公开聊天与源码资源；查看者不能发送消息或改变原工作区。
3. 点击“在线编辑”从当前产物创建本人的临时副本，保存源码后更新副本预览。
4. 点击“保存到我的作品”将当前副本长期保存。临时编辑和长期作品是两种保存状态。
5. 从“我的作品”再次编辑自己的作品，保存只更新自己的作品；也可下载 ZIP。
6. 原作者撤回公开后广场访问失效，但其他人此前保存的个人作品仍保留。

## 数据与权限

| 内容 | 存储位置 | 生命周期与归属 |
| --- | --- | --- |
| 发布状态 | MySQL `d2c_session_share` | 一会话一条；创建者管理，历史个人会话兼容工作区拥有者 |
| 临时编辑 | Redis 独立命名空间 | 用户与来源隔离，两小时到期 |
| 个人作品信息 | MySQL `d2c_saved_work` | 本人长期保存，修订控制 |
| 个人作品源码与资源清单 | MySQL `d2c_saved_work_file` | 按作品修订冻结，图片引用不可变对象 |
| 预览构建产物 | 本地 preview cache | 短票据，通过 H5/RN 同源预览网关读取 |
| 图片原始内容 | 现有对象存储 | 校验大小与摘要，源码不会保存上传凭据 |

## 开发与部署

- 业务契约和实现边界见 [会话广场主题](../topics/d2c-session-plaza.md)。
- 接口在 `src/functions/d2c/sharing/routes.ts`；公开读取服务在 `sharing/service.ts`，独立编辑接线在 `sharing/runtime.ts`，个人作品在 `savedWork/service.ts`。
- 发布前审核执行 [新增三表 SQL](../req-docs/d2c-session-plaza_迁移.sql)。SQL 不更改原会话与工作区表，不自动公开历史数据。
- 未登录不允许访问；团队成员可共同开发，但不能替会话创建者公开；历史个人会话回退仅影响发布管理，不回填创建者身份。个人作品与原有暂存版本作品列表是不同的数据集合。
- 撤回、归属和修订冲突均由服务端检查；前端没有应用回原工作区的入口，编辑服务也直接拒绝此操作。
